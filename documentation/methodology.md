# Compliance Assessment Methodology - TechNova Solutions



**Project:** Mini Compliance Program

**Frameworks:** ISO/IEC 27001:2022 and NIST SP 800-53 Rev. 5

**Document Owner:** GRC Analyst

**Version:** 1.0

**Assessment Date:** 10 November 2026



## 1. Purpose



This document explains the methodology used to assess information security risks, review security controls, identify compliance gaps and track remediation activities at TechNova Solutions.



The methodology provides a consistent approach for evaluating the organization's security posture against selected requirements from ISO/IEC 27001:2022 and NIST SP 800-53 Rev. 5.



## 2. Assessment Approach



The assessment follows these activities:



1. Define the assessment scope and objectives.

2. Identify information assets and assign proposed owners and classifications.

3. Identify information security risks affecting the assets.

4. Assess risks using likelihood and impact scores.

5. Identify relevant security controls from the selected frameworks.

6. Evaluate control implementation and maturity based on available evidence.

7. Identify gaps between expected and observed security practices.

8. Recommend corrective actions and assign responsible owners.

9. Record evidence and track remediation progress.

10. Review the assessment periodically and update documentation.



## 3. Frameworks Used



### ISO/IEC 27001:2022



ISO/IEC 27001:2022 provides requirements for establishing, implementing, maintaining and continually improving an Information Security Management System (ISMS).



This project uses selected Annex A controls as references for assessing information security practices.



### NIST SP 800-53 Rev. 5



NIST SP 800-53 Rev. 5 provides a catalog of security and privacy controls for information systems and organizations.



This project uses selected control families and control references to support the control assessment.



**Note:** The framework mappings in this project are indicative cross-references. They should be validated against the official framework requirements before being used in a real compliance assessment.



## 4. Asset Identification and Classification



Information assets are recorded in the Asset Register.



Each asset is assigned:



- A unique asset identifier.

- An asset name and category.

- A business purpose or description.

- A proposed asset owner.

- An information classification.



The classification levels used are Public, Internal, Confidential and Restricted.



## 5. Risk Assessment Method



Risks are evaluated using a qualitative scoring approach.



**Risk Score = Likelihood x Impact**



Likelihood and impact are scored from 1 to 5.



| Score | Risk Rating |

|---|---|

| 1-4 | Low |

| 5-9 | Medium |

| 10-16 | High |

| 17-25 | Critical |



Risks are recorded in the Risk Register with a description, score, rating, owner and proposed treatment.



Risk owners are responsible for reviewing assigned risks and tracking treatment activities.



## 6. Control Assessment Method



Security controls are documented in the Information Security Control Matrix.



Each control is assessed using:



- Control ID and description.

- ISO/IEC 27001:2022 reference.

- NIST SP 800-53 Rev. 5 reference.

- Assigned control owner.

- Implementation status.

- Current maturity level.

- Expected evidence.



Control implementation status uses the following categories:



| Status | Description |

|---|---|

| Implemented | Evidence supports that the control is operating |

| Partially Implemented | Some control activities are operating |

| Not Implemented | The control is not operating |

| Not Assessed | Insufficient assessment has been performed |

| Not Applicable | The control does not apply, with justification |



## 7. Maturity Assessment



The project uses a maturity scale from 0 to 5.



| Level | Maturity | Description |

|---:|---|---|

| 0 | Non-existent | No defined control activity |

| 1 | Initial | Informal or inconsistent activity |

| 2 | Developing | Basic process exists but is not fully standardized |

| 3 | Defined | Documented and consistently followed process |

| 4 | Managed | Measured and regularly monitored process |

| 5 | Optimized | Continuously improved process |



Maturity scores are preliminary assumptions until supported by sufficient evidence.



## 8. Evidence Collection and Validation



Evidence is recorded in the Evidence Register.



Examples of evidence include:



- Approved information security policies.

- Asset inventory records.

- Access review reports.

- Multi-factor authentication configuration records.

- Vulnerability assessment reports.

- Backup and recovery test results.

- Security logs and monitoring alerts.

- Change management approvals.

- Incident response records.



Evidence should be relevant, traceable, dated and associated with the control or risk it supports.



A proposed control or documented procedure alone does not prove that a control is operating effectively.



## 9. Gap Assessment and Remediation



Gaps are identified by comparing expected control requirements with available implementation information and evidence.



Each identified gap should include:



- A unique gap identifier.

- A description of the issue.

- The affected control or requirement.

- Potential business or security impact.

- A recommended corrective action.

- A responsible owner.

- A target completion date.

- A remediation status.



High and critical risks should receive priority attention.



## 10. Review and Reporting



The assessment documentation should be reviewed at least quarterly and whenever significant changes occur in the organization's systems, processes or risk environment.



Assessment results should be communicated to relevant stakeholders and management.



Updates should be recorded in the appropriate registers and supporting documents.



## 11. Assumptions and Limitations



This is a simulated compliance assessment for the fictional organization TechNova Solutions.



The assessment is based on proposed assets, control requirements, risk scenarios and maturity assumptions. It is not based on a verified production environment, formal interviews or independently tested evidence.



No certification, audit opinion or formal compliance conclusion is claimed.
